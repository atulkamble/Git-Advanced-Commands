# Git Conflict Resolution and Rollback Commands

## 1. Git Reset – Move HEAD to a Previous Commit

Purpose: Move the current branch to a previous commit and optionally remove changes from the staging area or working directory.

```
git log --oneline

git reset --soft HEAD~1

git reset --mixed HEAD~1

git reset --hard HEAD~1

git reset --hard <commit-id>
```

| Command             | Commit                      | Staging Area | Working Directory |
| ------------------- | --------------------------- | ------------ | ----------------- |
| `git reset --soft`  | Removed from branch history | Preserved    | Preserved         |
| `git reset --mixed` | Removed from branch history | Reset        | Preserved         |
| `git reset --hard`  | Removed from branch history | Reset        | Reset             |

Note: Avoid `git reset --hard` when you have important uncommitted changes. It can permanently discard them.

## 2. Git Revert – Safely Reverse a Commit

Purpose: Undo a previous commit by creating a new commit without rewriting existing history.

```
git log --oneline

git revert HEAD

git revert <commit-id>

git revert --no-commit <commit-id>

git status

git log --oneline
```

Example:

```
echo "Version 1" > app.txt
git add .
git commit -m "Version 1"

echo "Version 2" > app.txt
git add .
git commit -m "Version 2"

git revert HEAD
```

The second commit is reversed through a new commit, preserving the original history.

## 3. Git Restore – Restore Files and Unstage Changes

Purpose: Restore files in the working directory or remove files from the staging area.

```
git status

git restore app.txt

git restore .

git restore --staged app.txt

git restore --staged .

git restore --source=HEAD~1 app.txt

git restore --source=<commit-id> app.txt
```

| Command                               | Purpose                                             |
| ------------------------------------- | --------------------------------------------------- |
| `git restore app.txt`                 | Discard unstaged changes                            |
| `git restore .`                       | Discard unstaged changes in the current directory   |
| `git restore --staged app.txt`        | Unstage a file                                      |
| `git restore --staged .`              | Unstage all staged changes in the current directory |
| `git restore --source=HEAD~1 app.txt` | Restore a file from the previous commit             |

## 4. Git Merge Conflict Resolution

Purpose: Resolve conflicts when two branches modify the same lines of a file.

```
git switch -c feature

nano app.txt

git add .
git commit -m "Feature changes"

git switch main

nano app.txt

git add .
git commit -m "Main changes"

git merge feature

git status
```

Example conflict:

```
<<<<<<< HEAD
Changes from main branch
=======
Changes from feature branch
>>>>>>> feature
```

Edit the file, remove conflict markers, and keep the desired content.

```
nano app.txt

git add app.txt

git commit -m "Resolved merge conflict"

git log --oneline --graph --all
```

To cancel an unfinished merge:

```
git merge --abort
```

## 5. Git Reset vs Revert vs Restore

| Feature                   | Reset                     | Revert                 | Restore                         |
| ------------------------- | ------------------------- | ---------------------- | ------------------------------- |
| Main purpose              | Move branch HEAD          | Undo committed changes | Restore file content            |
| Rewrites history          | Yes, when moving backward | No                     | No                              |
| Creates new commit        | No                        | Yes                    | No                              |
| Works on files            | Limited                   | Commit-level           | Yes                             |
| Shared branch suitability | Use caution               | Recommended            | Suitable for local file changes |
| Common use                | Undo local commits        | Undo pushed commits    | Discard or unstage changes      |

## 6. Hands-on Practice Commands

Run these commands in a new practice directory:

```
mkdir git-rollback-lab
cd git-rollback-lab

git init
git branch -M main

git config user.name "Git Student"
git config user.email "student@example.com"

echo "Version 1" > app.txt
git add .
git commit -m "Initial commit"

echo "Version 2" > app.txt
git add .
git commit -m "Second commit"

echo "Version 3" > app.txt
git add .
git commit -m "Third commit"

git log --oneline

git reset --soft HEAD~1
git status

git reset --mixed HEAD
git status

git restore app.txt
git status

git revert HEAD
git log --oneline

echo "Temporary changes" >> app.txt
git status

git restore app.txt
git status

echo "Staged changes" >> app.txt
git add app.txt

git restore --staged app.txt
git status
```

## Points to Remember

- Reset: Move HEAD and potentially rewrite local commit history.
- Revert: Undo a committed change while preserving history.
- Restore: Discard local file modifications or unstage files.
- Merge conflicts: Manually resolve conflicting content, stage the resolution, and complete the merge.
- Best practice: Use `git revert` for commits already pushed to a shared branch; use `git reset` primarily for local, unpublished commits.
